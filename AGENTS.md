# AI Agents & Architecture Guidelines (AGENTS.md)

Этот документ определяет роли ИИ-ассистентов, архитектурные правила и стандарты проектирования для проекта "Планировщик Участка". Используйте этот файл как контекст для AI (Cursor, Cline, Claude, GPT).

---

## 🎨 Общие принципы разработки (Core Philosophy)

1. **YAGNI & KISS:** Пишем код для текущей итерации MVP. Не усложняем раньше времени, но оставляем точки расширения (инверсия зависимостей).
2. **Single Source of Truth:** Размеры участка и координаты объектов — главная правда. Фронтенд только визуализирует то, что отдал бэкенд.
3. **Vibe-Coding Friendly:** Код должен быть модульным, чтобы ИИ мог изолированно менять UI или логику бэкенда, не ломая соседние модули.

## 🛠 Роли ИИ-Агентов (Agent Personas)

### 1. Backend Engineer (Go)

**Контекст:** Разработка отказоустойчивого, легковесного API на Go.
**Правила проектирования:**

- **Архитектура:** Использовать упрощенную Чистую Архитектуру (Clean Architecture):
  - `domain/` — чистые структуры (Plot, Expense, Task), интерфейсы репозиториев, бизнес-логика. Никаких внешних зависимостей.
  - `repository/` — реализация работы с PostgreSQL (использовать `pgx` или `sqlx`, чистый SQL).
  - `delivery/http/` — обработчики (handlers), валидация входящих запросов, маршруты.
- **Данные и 3D-задел:**
  - Координаты объектов хранить в метрах (float64) в декартовой системе: `x`, `y`, `z` (пока по умолчанию `0.0`), `width`, `length`, `height` (высота для будущего 3D).
  - Для денег (`Expenses`) строго использовать тип `numeric` в БД и кастомный тип/строку в Go для избежания проблем с округлением float.
- **Ошибки:** Возвращать понятные типизированные ошибки из слоев логики, мапить их в HTTP-статусы на уровне доставки.

### 2. Frontend Engineer (Next.js & UI)

**Контекст:** Разработка интерфейса на Next.js (App Router), TypeScript, Tailwind CSS.
**Правила проектирования:**

- **Компоненты и дизайн-система:**
  - Использовать headless-примитивы актуального пакета **Base UI** (`@base-ui/react`) через локальные типизированные обёртки в `components/ui/`.
  - Кнопки, поля, select, tabs, dialog и другие интерактивные элементы не реализовывать повторно внутри feature-модулей.
  - Стилизация выполняется Tailwind CSS; общие focus, invalid, disabled и responsive-состояния задаются в UI-слое.
- **Формы:**
  - Все формы строить на **React Hook Form**, схемы и преобразование входных данных — на **Zod** через `@hookform/resolvers`.
  - Не хранить состояние отдельных форм в Zustand и не читать формы вручную через `FormData`.
  - Серверные ошибки полей мапить в React Hook Form через `setError`; денежные значения оставлять строками.
- **Стейт-менеджмент:** Легковесный Zustand. Стейт должен разделять:
  - Данные сервера (кэш участка, расходов).
  - Локальный стейт редактора (выбранный объект, режим 2D/3D, масштаб, сетка).
- **Визуализация 2D/3D:**
  - Точный план рендерить изолированным SVG-компонентом `PlotCanvas.tsx`, 3D — через **React Three Fiber**, `three` и **Drei** в `Plot3DScene.tsx`.
  - Оба режима получают одни и те же метрические доменные данные; визуализаторы не становятся источником истины.
  - Преобразования координат, расчёт масштаба и камеры держать в чистых тестируемых утилитах feature-модуля.
  - WebGL-сцену загружать динамически без SSR и всегда сохранять доступный 2D fallback.
  - До появления отдельного сценария 3D остаётся режимом просмотра и выбора; точные изменения выполняются через типизированные формы.
  - Перемещение объектов в 2D реализовывать Pointer Events с pointer capture для мыши и touch; координаты snap-ятся к шагу сетки и ограничиваются границами участка.
  - Сервер остаётся источником истины: canvas показывает локальный preview, а после drop сохраняет только `x/y` через типизированный API и откатывается при ошибке.
  - План должен оставаться usable на ширине 360px: не использовать обязательную фиксированную ширину canvas, поддерживать touch-target не менее 44px и не ломать прокрутку страницы.
  - Бренд фронтенда — `baibakovkir` с подписью «сервис планировщика участка»; favicon и OG-ассеты строить из единого SVG-источника.
  - Публичные metadata, robots и sitemap не должны раскрывать инфраструктуру; приватные маршруты приложения закрывать от индексации.
  - Вертикальные координаты signed: отрицательный `z` разрешает подземные коммуникации и уровни.
  - Новые элементы расширяются через тип и geometry (`footprint`, `polygon`, `polyline`), а нестандартные свойства не требуют изменения enum и хранятся в properties.

### 3. DevOps & CI/CD Specialist

**Контекст:** Настройка пайплайнов GitHub Actions и инфраструктуры.
**Правила проектирования:**

- Пайплайн должен быть разбит на джобы (Backend и Frontend) для экономии времени раннеров.
- **Бэкенд:** Проверка `golangci-lint`, запуск `go test -v ./...`.
- **Фронтенд:** Проверка `eslint`, запуск `npm run build`.
- Production-образы публиковать с immutable SHA-тегами; deploy сериализовать и завершать healthcheck.
- Перед обновлением выполнять backup, при неуспешном healthcheck возвращать предыдущий образ. Миграции должны быть обратно совместимыми, так как rollback образа не откатывает БД.
- Адреса серверов, домены, SSH-пользователи, ключи, registry credentials и production URL хранить только в GitHub Environment variables/secrets или защищённом env на сервере.
- README и tracked-конфигурация должны оставаться обезличенными; инфраструктурные файлы в `ops/` являются шаблонами.

## 🚀 Чек-лист для ИИ перед выдачей кода (AI Verification)

Перед тем как показать код пользователю, убедись, что:

1. В Go коде нет хардкода строк подключения к БД (все через `ENV`).
2. В Next.js типы TypeScript строго описаны (никаких `any`).
3. Координатная сетка инкапсулирована и готова к масштабированию.
4. Выданы файлы конфигурации GitHub Actions (`.github/workflows/ci.yml`).
5. Интерактивные frontend-компоненты используют общий Base UI слой, а формы — React Hook Form + Zod.
6. В tracked-файлах нет production IP, SSH user, приватного домена или секретов.
