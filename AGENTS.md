# AI Agents & Architecture Guidelines (AGENTS.md)

Этот документ определяет роли ИИ-ассистентов, архитектурные правила и стандарты проектирования для проекта "Планировщик Участка". Используйте этот файл как контекст для AI (Cursor, Cline, Claude, GPT).

---

## 🎨 Общие принципы разработки (Core Philosophy)
1. **YAGNI & KISS:** Пишем код для текущей итерации MVP. Не усложняем раньше времени, но оставляем точки расширения (инверсия зависимостей).
2. **Single Source of Truth:** Размеры участка и координаты объектов — главная правда. Фронтенд только визуализирует то, что отдал бэкенд.
3. **Vibe-Coding Friendly:** Код должен быть модульным, чтобы ИИ мог изолированно менять UI или логику бэкенда, не ломая соседние модули.

## 🛠 Роли ИИ-Агентов (Agent Personas)

### 1. Backend Engineer (Go)
**Контекст:** Разработка отказоустойчивого, легковесного API на Go.
**Правила проектирования:**
- **Архитектура:** Использовать упрощенную Чистую Архитектуру (Clean Architecture):
  - `domain/` — чистые структуры (Plot, Expense, Task), интерфейсы репозиториев, бизнес-логика. Никаких внешних зависимостей.
  - `repository/` — реализация работы с PostgreSQL (использовать `pgx` или `sqlx`, чистый SQL).
  - `delivery/http/` — обработчики (handlers), валидация входящих запросов, маршруты.
- **Данные и 3D-задел:** 
  - Координаты объектов хранить в метрах (float64) в декартовой системе: `x`, `y`, `z` (пока по умолчанию `0.0`), `width`, `length`, `height` (высота для будущего 3D).
  - Для денег (`Expenses`) строго использовать тип `numeric` в БД и кастомный тип/строку в Go для избежания проблем с округлением float.
- **Ошибки:** Возвращать понятные типизированные ошибки из слоев логики, мапить их в HTTP-статусы на уровне доставки.

### 2. Frontend Engineer (Next.js & UI)
**Контекст:** Разработка интерфейса на Next.js (App Router), TypeScript, Tailwind CSS.
**Правила проектирования:**
- **Стейт-менеджмент:** Легковесный Zustand. Стейт должен разделять:
  - Данные сервера (кэш участка, расходов).
  - Локальный стейт редактора (выбранный объект, режим перемещения, сетка).
- **Визуализация (2D с заделом на 3D):**
  - MVP рендерится через **SVG** или **HTML5 Canvas** в изолированном компоненте `PlotCanvas.tsx`.
  - Все расчеты (трансформация метров в пиксели экрана, зум, сетка) вынести в чистые утилиты `utils/geo.ts`.
  - Компонент должен принимать массив объектов с метрическими координатами и трансформировать их на лету. Это позволит в будущем заменить `PlotCanvas.tsx` на `Plot3DScene.tsx` (React Three Fiber) без изменения логики данных.

### 3. DevOps & CI/CD Specialist
**Контекст:** Настройка пайплайнов GitHub Actions и инфраструктуры.
**Правила проектирования:**
- Пайплайн должен быть разбит на джобы (Backend и Frontend) для экономии времени раннеров.
- **Бэкенд:** Проверка `golangci-lint`, запуск `go test -v ./...`.
- **Фронтенд:** Проверка `eslint`, запуск `npm run build`.

## 🚀 Чек-лист для ИИ перед выдачей кода (AI Verification)
Перед тем как показать код пользователю, убедись, что:
1. В Go коде нет хардкода строк подключения к БД (все через `ENV`).
2. В Next.js типы TypeScript строго описаны (никаких `any`).
3. Координатная сетка инкапсулирована и готова к масштабированию.
4. Выданы файлы конфигурации GitHub Actions (`.github/workflows/ci.yml`).
